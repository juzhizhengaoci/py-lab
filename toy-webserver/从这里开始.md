## 3. ⚠️ 三个 Windows 坑（我已经替你踩过了）

### 坑 1：`telnet` 你这台机器上**没有**

教程第 6 步让你 `telnet localhost 8888` 然后手打 `GET /hello HTTP/1.1`。
**实测：`C:\Windows\System32\telnet.exe` 不存在**，Windows 默认不装。你敲下去只会得到"不是内部或外部命令"。

**方案 B（推荐，零配置，现在就能用）** —— 用 Python 自己当浏览器：

再开一个终端，激活同一个 venv，输入 `python` 进入交互模式，然后**一行一行敲**：

```python
import socket
s = socket.create_connection(('localhost', 8888))
s.sendall(b'GET /hello HTTP/1.1\r\n\r\n')
print(s.recv(4096).decode())
```

**最后一行会打印出服务器的原始响应。** 这才是 Part 1 真正要你看的东西。

> 比 telnet 更好的一点：`s.sendall(...)` 里那个字符串你**可以随便改**。
> 改成 `b'asdfgh\r\n\r\n'` 再敲一遍试试——教程说照样返回 `Hello, World!`，自己验证一下是不是真的。
> 这条"服务器根本不管你说什么"的发现，比读十遍文章管用。

**方案 A（想要原汁原味的 telnet 体验）** —— 装 Windows 自带客户端：

`Win + R` → 输入 `optionalfeatures` → 回车 → 勾选 **"Telnet 客户端"** → 确定（会弹一次 UAC，点"是"）。
装完后 `telnet localhost 8888` 就能用了。

> 不急的话用方案 B 就行，别为了仪式感去折腾系统功能。

### 坑 2：端口 8888 是空的，但 8000 被占着

你之前后台跑着一个 `python -m http.server 8000`（PID 24676），现在还活着。
**教程用 8888，不冲突，不用管它。** 但如果哪天你想用 8000，得先把它关掉：`taskkill /PID 24676 /F`

### 坑 3：`.venv` 绝不能提交进 git

已经替你在 `.gitignore` 里写好了。**别手贱改它**——venv 里有几千个文件，提交一次能让你这辈子都不想再碰 git。
